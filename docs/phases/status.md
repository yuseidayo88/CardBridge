## 2. 今回追加したもの

### 2.1 カード名対応表 — AIキーが「必須」でなくなりました

以前の報告で「AI層が動かない」としていた根拠は、`cardNameEn` の1項目でした。
`buildEbayTitle` がこれを要求し、無ければ `evaluateEligibility` が
`MISSING_CARD_NAME_EN` で出品をブロックします。

そして「リザードンex → Charizard ex」は**変換ではなく照合**です。
ローマ字化すると "Rizadon ex" になり、eBayでは誰も検索しません。

**モデルに聞くより対応表のほうが良い理由**は、コストではありません。
知らないカードを渡されたモデルは、それでも**もっともらしい英語名を出します**。
そして、もっともらしい誤りは、承認する人の目には正しく見えます。
対応表は、答えを持っているか、持っていないと言うかのどちらかです。

照合は段階的です。

| 一致条件           | 信頼度 | 自動出品                        |
| ------------------ | ------ | ------------------------------- |
| 名前＋セット＋番号 | 1.00   | ○                               |
| 名前＋番号         | 0.95   | ○                               |
| 名前のみ           | 0.70   | **×**（既定しきい値 0.85 未満） |
| 英語名が複数該当   | —      | **値を返さない**                |

名前のみの一致を 0.85 未満に置いているのは、同名カードが複数セットに
再録されるためです。「たいてい正しい」は、まさに人が見るべき状態です。

複数該当時に**片方を選ばない**のは、選べば別のカードの英語名で出品されるからで、
それはこの表が防ぐために存在している失敗そのものです。
一方、同じ英語名が複数セットに載っているだけなら矛盾ではありません
（矛盾扱いにすると人気カードが永久に解決不能になります）。

未確認行は使えますが、信頼度がしきい値未満に抑えられます。
DB側も、確認済みを主張する行には**確認者名を要求**します
（誰の名前も無い確認済み行は、バグが立てたものと区別できません）。

管理画面 `/settings/card-names` から1件追加・一括取り込み・確認・削除ができます。

### 2.2 AI プロバイダ実装（Anthropic / OpenAI）

抽象だけだった `AiProvider` に実装が付きました。両方とも:

- 指示は専用チャネル（Anthropic は `system` フィールド、OpenAI は system ロール）、
  店舗テキストは user ターン。**プロンプトインジェクション対策をテストで固定**
- 途中で切れた応答は**握りつぶさず失敗**させます。切れたJSONはしばしばパースでき、
  途中で終わった説明文は、見える失敗より質が悪いためです
- 429 と 5xx は再試行、400 は再試行しません（壊れたリクエストの再送はコストだけ）

`AI_PROVIDER` が未知の値なら**例外**にします。既定ベンダーへのフォールバックは、
意図しない請求先と、誰も想定していない出力を生みます。

### 2.3 eBay Metadata クライアント

ハードコードを拒否してきた値（Condition ID、Descriptor ID とその許容値、
カテゴリが受け付ける Item Specifics）を実際に取得する層です。

**カテゴリツリーIDを推測しません。** 「US はツリー0」を既定にすると、
別マーケットプレイスに対して**もっともらしい別の aspect** が返り、
呼び出し漏れよりはるかに気づきにくい誤りになります。

`SELECTION_ONLY` と `FREE_TEXT` の区別は正規化後も保持します。
SELECTION_ONLY に自由記述を送ると、警告ではなく**出品拒否**です。

### 2.4 相場観測（Browse API）

**このモジュールで最も重要なのは、できないことです。**

Browse API は**出品中の商品しか見えません**。それは「売れた価格」ではなく
「売り手の希望価格」です。販売済みデータの入手経路は塞がっています。

- Marketplace Insights: Limited Release、新規受付停止
- findCompletedItems: 2025年2月に廃止

そのため `isSufficient` は**リテラル型の `false`** です。200件の出品を
食わせても false のままであることをテストで固定しています。
`activeCount` が大きいことを市場の裏付けと取り違えて、
他の売り手の希望価格に合わせて仕入れる、という事故を型で防いでいます。

異なる通貨の出品は**換算せず除外**します。ここで換算すると、
為替レートが相場観測の内部に埋まり、利益率が合わないときに誰も探しに来ません。

中央値は実在する観測値です（2件の平均を取ると、どの出品にも存在しない価格が生まれます）。
並べ替えは10進文字列を桁で比較します。辞書順だと `"1000" < "99"` となり、
**最も高い出品が最安値として記録されます**。

| #   | 条件                            | 場所                                  |
| --- | ------------------------------- | ------------------------------------- |
| 1   | `DRY_RUN=false`                 | 環境変数（文字列 `false` のときのみ） |
| 2   | `ALLOW_PRODUCTION_PUBLISH=true` | 環境変数                              |

| 4   | 実行回数が上限未満              | `MAX_PUBLISH_PER_RUN`                 |

規約ではなく**型で強制**しています。今回追加した Metadata と Browse は
どちらも読み取り専用なので、この経路には一切触れません。
